# StudyTracker

StudyTracker is a backend learning project built with C# and ASP.NET Core.

The goal of this project is to practice real backend architecture using REST API, layered structure, dependency injection, Entity Framework Core, SQLite, Repository Pattern, DTOs, service layer, migrations, and API documentation with Scalar/OpenAPI.

This is not a production-ready system yet. It is an MVP created to understand how a backend application is structured and how data flows from an HTTP request to a database.

## Project Status

MVP v1 in progress.

Current features:

* Create study sessions
* List study sessions
* Search study session by Id
* Search study sessions by subject
* Update study sessions
* Delete study sessions
* Persist data using SQLite
* Use Entity Framework Core migrations
* Test API endpoints with Scalar UI

## Architecture

The project follows a layered structure:

```text
HTTP Client / Scalar
↓
Controller
↓
Service
↓
Repository
↓
DbContext
↓
SQLite
```

### StudyTracker.Api

Responsible for receiving HTTP requests and returning HTTP responses.

It contains the Controllers, API configuration, dependency injection setup, OpenAPI and Scalar configuration.

### StudyTracker.Core

Contains the central business logic of the application.

It includes Models, DTOs, Interfaces, Services and operation result classes.

The Core layer does not depend directly on SQLite, Entity Framework Core or ASP.NET Core.

### StudyTracker.Infrastructure

Contains external implementation details.

It is responsible for database access using Entity Framework Core and SQLite.

### StudyTracker.Console

Auxiliary console application used for learning and testing the service layer from the terminal.

## API Endpoints

### List all study sessions

```http
GET /api/sessoes-estudo
```

### Get study session by Id

```http
GET /api/sessoes-estudo/{id}
```

### Search study sessions by subject

```http
GET /api/sessoes-estudo/buscar?materia=C#
```

### Create study session

```http
POST /api/sessoes-estudo
```

Example body:

```json
{
  "materia": "C#",
  "topico": "Entity Framework Core",
  "minutosEstudados": 60,
  "dificuldade": 3
}
```

### Update study session

```http
PUT /api/sessoes-estudo/{id}
```

Example body:

```json
{
  "materia": "ASP.NET",
  "topico": "API architecture",
  "minutosEstudados": 120,
  "dificuldade": 4
}
```

### Delete study session

```http
DELETE /api/sessoes-estudo/{id}
```

## How to Run the Project

Clone the repository and restore the packages:

```bash
dotnet restore
```

Build the solution:

```bash
dotnet build
```

Apply the database migrations:

```bash
dotnet ef database update --project .\StudyTracker.Infrastructure\StudyTracker.Infrastructure.csproj --startup-project .\StudyTracker.Api\StudyTracker.Api.csproj
```

Run the API:

```bash
dotnet run --project .\StudyTracker.Api\StudyTracker.Api.csproj
```

Open Scalar UI in the browser:

```text
http://localhost:5239/scalar
```

The port may change depending on the local launch settings.

## Database

The project uses SQLite for local persistence.

The local database file is not meant to be versioned in GitHub. It should be generated locally using Entity Framework Core migrations.

The migrations are versioned because they represent the database structure, not the database data.

## Git and Security Notes

The repository should not include:

* Local database files
* `.env` files
* Secrets
* API keys
* Tokens
* Certificates
* Passwords
* Build output folders such as `bin/` and `obj/`

The `.gitignore` file is included to prevent local and sensitive files from being committed.
